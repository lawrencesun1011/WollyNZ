## 产品概述

项目先后经历过 CloudBase、EdgeOne 等多次改版，最终定型为 Cloudflare Pages + Supabase。每次改版都留下了部分残留：旧部署配置、旧后端目录、重构后失去引用的组件、已废弃的依赖。本次任务是在**完全不改变线上功能与视觉**的前提下，做一次可回滚的安全清理，让项目结构重新对应于当前架构。

## 核心范围

1. 删除旧架构遗留：`Dockerfile`、`cloudbase/` 整个目录、误创建的 `--full-page` 截图
2. 清除死代码：6 个确认无任何引用的文件，以及 5 个空目录
3. 清理废弃依赖与 npm scripts
4. 整理数据脚本位置，使 `scripts/` 成为唯一的脚本目录
5. 把过时的需求文档重写为当前架构
6. 全量验证（类型检查、规范检查、构建）并部署上线

## 已与用户确认的四项决策

## 实施策略

采用**先删后验、分批提交**的策略：先物理删除已确认无用的文件与目录，再删除死代码，然后清理依赖与脚本，最后统一跑类型检查、规范检查、构建与部署。每批次范围小且可独立验证，任一环节失败都能精确定位到具体文件。

关键安全约束：所有判定为"可删"的条目都已完成交叉验证（全项目搜索引用 + LSP `findReferences`），并且工作区处于干净状态，误删可用 `git checkout` 逐文件恢复。

## 脚本位置整理

`src/scripts/fetch-data.mjs` → 移动到 `scripts/fetch-data.mjs`，与 `prepare-static-data.mjs`、`optimize-images.mjs` 并列。

该文件当前被 `cloudbase/functions/fetch-data/index.mjs` import，但 cloudbase 目录会在前一步整体删除，因此移动后无残留引用。移动时需同步修正脚本内部的路径常量：

```
const DATA_DIR = join(__dirname, "..", "..", "data");  // 原：src/scripts/ → 根/data
```

移动后 `scripts/` 下应为 `join(__dirname, "..", "data")`，**必须修改**，否则数据会写错位置。

## 验证要求

按顺序执行，任一失败立即停止定位：

1. `git status` / `git diff --stat` 复核删除范围，确认未误删在用文件
2. `npx tsc --noEmit`
3. `npx eslint`
4. `rm -rf .next && npm run build`（在 CodeBuddy 内构建可能遇 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`，系 IDE 批量删除保护误拦，先 `rm -rf .next` 即可，非项目问题）
5. 构建产物抽查：确认 `out/guide.html`、`out/index.html` 存在且内容完整
6. `npx wrangler pages deploy out --project-name=goalnz`，验证 `https://goalnz.pages.dev` 与 `https://goalnz.pages.dev/guide` 均返回 HTTP 200
